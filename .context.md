# JAKA ROS2 Workspace - Codebase Context

## Overview
This is a **ROS 2 Humble** workspace for **JAKA collaborative robots** (cobots), providing a complete driver, motion planning (MoveIt 2), and simulation stack. It uses **JAKA SDK v2.2.2** (proprietary shared library `libjakaAPI.so`) to communicate with the robot controller over TCP/IP. The workspace targets **Ubuntu 22.04** and optionally integrates **Gazebo Ignition Fortress** for simulation.

**Repository**: https://github.com/JakaCobot/jaka_ros2 (migrating to https://github.com/JAKARobotics)  
**Version**: 1.1.0

## Package Structure (under `src/`)

### 1. `jaka_driver` — Robot Driver Node
- **Source**: `src/jaka_driver.cpp` (989 lines, main driver node)
- **Executables**: `jaka_driver`, `sdk_test`, `client`, `servoj_demo`
- **Launch**: `robot_start.launch.py` — starts driver with `ip:=<robot_ip>` parameter
- **SDK headers**: `include/jaka_driver/` — `JAKAZuRobot.h`, `jktypes.h`, `jkerr.h`, `conversion.h`
- **SDK library**: `lib/libjakaAPI.so`
- **Dependencies**: rclcpp, std_msgs, geometry_msgs, sensor_msgs, jaka_msgs, action_msgs, control_msgs, Eigen

#### Driver Node Functionality (`jaka_driver` node):
**Startup sequence**: login → power_on → wait 8s → enable_robot → wait 4s → start services/publishers

**ROS2 Services exposed** (under `/jaka_driver/` namespace):
| Service | Type | Description |
|---------|------|-------------|
| `linear_move` | jaka_msgs/srv/Move | Linear (Cartesian) motion |
| `joint_move` | jaka_msgs/srv/Move | Joint-space motion |
| `jog` | jaka_msgs/srv/Move | Jog motion (continuous) |
| `servo_move_enable` | jaka_msgs/srv/ServoMoveEnable | Enable/disable servo mode |
| `servo_p` | jaka_msgs/srv/ServoMove | Cartesian servo motion (incremental) |
| `servo_j` | jaka_msgs/srv/ServoMove | Joint servo motion (incremental) |
| `stop_move` | std_srvs/srv/Empty | Stop all motion |
| `set_toolframe` | jaka_msgs/srv/SetTcpFrame | Set TCP frame |
| `set_userframe` | jaka_msgs/srv/SetUserFrame | Set user coordinate frame |
| `set_payload` | jaka_msgs/srv/SetPayload | Set payload parameters |
| `drag_move` | std_srvs/srv/SetBool | Enable/disable free-drive (drag) mode |
| `set_collisionlevel` | jaka_msgs/srv/SetCollision | Set collision sensitivity (levels 0-5) |
| `set_io` / `get_io` | jaka_msgs/srv/SetIO / GetIO | Digital/analog I/O control |
| `get_fk` | jaka_msgs/srv/GetFK | Forward kinematics |
| `get_ik` | jaka_msgs/srv/GetIK | Inverse kinematics |

**ROS2 Topics published** (at ~10Hz from background thread):
| Topic | Type | Description |
|-------|------|-------------|
| `/jaka_driver/tool_position` | geometry_msgs/TwistStamped | TCP position (xyz + rpy in degrees) |
| `/jaka_driver/joint_position` | sensor_msgs/JointState | Joint positions (radians) |
| `/jaka_driver/robot_states` | jaka_msgs/RobotMsg | Robot state (motion/power/servo/collision) |

**Background threads**:
- `get_conn_scoket_state()` — monitors connection, publishes state at 100ms intervals
- `stop_jog_callback()` — wall timer (3s) auto-stops jog if no new jog commands

#### Additional Executables:
- **`client`** — Example ROS2 service client for `linear_move`
- **`servoj_demo`** — Demo of servo_j mode via service calls (200 incremental moves)
- **`sdk_test`** — Direct SDK testing (no ROS)

### 2. `jaka_planner` — MoveIt 2 Integration
- **Source**: `src/moveit_server.cpp` (277 lines), `src/moveit_test.cpp` (175 lines)
- **Executables**: `moveit_server`, `moveit_test`
- **Launch**: `moveit_server.launch.py` — starts with `ip:=<robot_ip> model:=<robot_model>`
- **Dependencies**: rclcpp, moveit_ros_planning_interface, moveit_visual_tools, moveit_core, rclcpp_action, control_msgs

#### `moveit_server` Node:
- Connects to robot, powers on, enables
- Creates **FollowJointTrajectory action server** at `/jaka_<model>_controller/follow_joint_trajectory`
- Publishes `/joint_states` at ~125Hz for MoveIt/RViz feedback
- Executes trajectories using SDK `servo_j()` in ABS mode with step_num = dt/0.008
- Waits for target position (±0.2° tolerance per joint) before reporting success
- Uses `servo_move_use_joint_LPF(0.5)` for filtering

#### `moveit_test` Node:
- Example MoveIt 2 motion planner client
- Uses `MoveGroupInterface` to plan and execute joint-space goals
- Runs 2 iterations of 3 predefined joint configurations + a final home position
- Planning group: `jaka_<model>` (default `zu3`)

**IMPORTANT**: `jaka_driver` and `moveit_server` **cannot run simultaneously** — they both connect to the same robot SDK.

### 3. `jaka_msgs` — Custom Message/Service Definitions
**Message**:
- `RobotMsg.msg` — `int16 motion_state, power_state, servo_state, collision_state`

**Services**:
| Service | Request | Response |
|---------|---------|----------|
| `Move.srv` | pose[], has_ref, ref_joint[], mvvelo, mvacc, mvtime, mvradii, coord_mode, index | ret, message |
| `ServoMove.srv` | pose[], speed[] | ret, message |
| `ServoMoveEnable.srv` | enable (bool) | ret, message |
| `GetFK.srv` | joint[] | cartesian_pose[], message |
| `GetIK.srv` | ref_joint[], cartesian_pose[] | joint[], message |
| `SetTcpFrame.srv` | pose[], tool_num | ret, message |
| `SetUserFrame.srv` | pose[], user_num | ret, message |
| `SetPayload.srv` | mass, xc, yc, zc, tool_num | ret, message |
| `SetCollision.srv` | is_enable, value | ret, message |
| `SetIO.srv` | type, index, signal, value | ret, message |
| `GetIO.srv` | type, index, signal, path | value, message |
| `ClearError.srv` | (unused) | ret, message |

### 5. `jaka_<model>_moveit_config` — MoveIt 2 Configuration Packages (one per robot model)
Each contains:
- **config/**:
  - `jaka_<model>.srdf` — Semantic Robot Description (planning groups, default states)
  - `kinematics.yaml` — KDL kinematics solver config
  - `moveit_controllers.yaml` — FollowJointTrajectory controller mapping
  - `joint_limits.yaml` — Joint velocity/acceleration limits
  - `ros2_controllers.yaml` — ros2_control controller definitions
  - `jaka_<model>.ros2_control.xacro` — Hardware interface xacro
  - `initial_positions.yaml` — Default joint positions
  - `pilz_cartesian_limits.yaml` — Pilz planner limits
  - `moveit.rviz` — RViz config
- **launch/**:
  - `demo.launch.py` — Main MoveIt 2 + RViz demo (parameter: `use_sim`)
  - `demo_gazebo.launch.py` — Gazebo simulation demo
  - `gazebo.launch.py` — Gazebo-only launch
  - `move_group.launch.py` — MoveIt move_group node
  - `moveit_rviz.launch.py` — RViz visualization
  - `rsp.launch.py` — Robot state publisher
  - `spawn_controllers.launch.py` — Controller spawning
  - `static_virtual_joint_tfs.launch.py` — Static TF for virtual joint

**Planning group name**: `jaka_<model>` (e.g., `jaka_zu3`)  
**Controller name**: `jaka_<model>_controller`  
**Action**: `/jaka_<model>_controller/follow_joint_trajectory`  
**Kinematics solver**: KDL (kdl_kinematics_plugin)

### 6. `launches.py` (workspace root)
A comprehensive 757-line Python launch file utility that generates modular launch descriptions for:
- Robot state publisher (`generate_rsp_launch`)
- MoveIt RViz (`generate_moveit_rviz_launch`)
- Setup assistant (`generate_setup_assistant_launch`)
- And more MoveIt/Gazebo integration functions

## Key Architecture

```
┌─────────────────────┐       ┌──────────────────────┐
│   MoveIt 2 / RViz   │       │     jaka_driver       │
│   (Planning +        │       │   (Direct control)    │
│    Visualization)    │       │                       │
└─────────┬───────────┘       └──────────┬────────────┘
          │                              │
          │ FollowJointTrajectory        │ ROS2 Services
          │ Action                       │ (move, servo, IO...)
          ▼                              │
┌─────────────────────┐                  │
│   moveit_server     │                  │
│   (Action Server)   │                  │
└─────────┬───────────┘                  │
          │                              │
          │ SDK servo_j()                │ SDK calls
          ▼                              ▼
┌──────────────────────────────────────────┐
│         libjakaAPI.so (JAKA SDK 2.2.2)   │
│         TCP/IP → Robot Controller        │
└──────────────────────────────────────────┘
```

**Two mutually exclusive operation modes:**
1. **Direct control**: `ros2 launch jaka_driver robot_start_launch.py ip:=<ip>` → use ROS2 services
2. **MoveIt planning**: `ros2 launch jaka_planner moveit_server.launch.py ip:=<ip> model:=<model>` + `ros2 launch jaka_<model>_moveit_config demo.launch.py`

## Technical Notes
- **SDK communication**: Proprietary binary `libjakaAPI.so` — no source available
- **SDK headers**: `JAKAZuRobot.h`, `jktypes.h`, `jkerr.h`, `conversion.h` define the C++ API
- **Rotation representation**: Uses Eigen for angle-axis ↔ rotation matrix ↔ RPY conversions
- **Servo mode**: 8ms control cycle (`servo_j` with step_num = dt/0.008)
- **Default robot IP**: `10.5.5.100`
- **Controller firmware**: min v1.7.1.46, recommended v1.7.2.16
- **C++ standard**: C++17
- **Build system**: CMake via ament_cmake + colcon
